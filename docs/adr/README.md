## Правила

1. `Accepted` не редактируется. Изменилось решение — новый ADR со статусом `Accepted`, старый получает `Superseded by NNNN`.
2. В `Context` — только факты и ограничения, без «нам захотелось».
3. В `Decision` — что именно делаем (структуры, границы, форматы), чтобы по ADR можно было писать код.
4. В `Consequences` — честно и минусы: что усложняется, что придётся поддерживать, какие риски принимаем.
5. Если решение можно отменить без миграции данных — это, скорее всего, не ADR, а заметка в PR.

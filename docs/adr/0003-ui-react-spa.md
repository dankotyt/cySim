# 0003. UI: React/Vite SPA с фиксированными компонентами

- **Статус:** Accepted
- **Дата:** 2026-11-12
- **Связано:** ADR-0007 (комната), ADR-0005 (корпус)

## Context

- Интерфейс — не форма, а среда: почтовый клиент, браузер с адресной строкой и панелью сертификата, телефон, просмотр PDF, диалог USB. Всё это живёт в одном рабочем столе и интенсивно меняет состояние.
- Сценарий задаёт объекты и цель, но не вёрстку (ADR-0007). Значит, UI должен уметь отрисовать любой объект по `kind` и данным артефакта.
- Нужны два кабинета: сотрудника (обучение, прогресс, разбор ошибок) и администратора (отделы, документы, правила, сценарии, аналитика).
- Разработчик один; при этом SPA выбран осознанно: среда с состоянием на серверных partials быстро превращается в кашу, а переиспользуемые компоненты (Mail, Browser) понадобятся и в обучении, и в предпросмотре для админа.
- Русский язык — единственный, но строки должны быть вынесены, чтобы не пришлось переписывать компоненты.

## Decision

**React 18 + TypeScript + Vite, отдельный каталог `frontend/`; FastAPI остаётся API-сервером.**

| Слой | Решение |
|---|---|
| Сборка | Vite, `npm ci`, прод-сборка в `frontend/dist`, раздаётся backend'ом как статика |
| Роутинг | React Router (routes: `/desk`, `/desk/mail/:id`, `/desk/browser`, `/desk/call`, `/cabinet`, `/admin`) |
| Серверное состояние | TanStack Query, кэш по ключам `['scenario', id]`, `['mailbox']` и т.д. |
| Стили | Tailwind + собственные design tokens; без тяжёлого UI-кита |
| Иконки | lucide-react |
| Типы API | генерация из OpenAPI (`openapi-typescript`), `npm run gen:api` |
| Тесты | Vitest (компоненты), Playwright (один сквозной сценарий) |
| Язык | ru-RU, строки в `src/shared/i18n` |

### Фиксированные компоненты

`DesktopShell`, `MailApp` (список + письмо + вложения), `BrowserApp` (вкладки, адресная строка, панели «Сертификат»/«WhoIS», история), `PhoneApp` (входящий звонок, скрипт, кнопки), `PdfViewer`, `UsbDialog`, `CoachPanel` (обратная связь и микро-урок), `AdminCabinet`.

Правило: **компонент рендерит данные, а не разметку от LLM**. `dangerouslySetInnerHTML` запрещён вне `BrowserApp`, где HTML корпуса показывается только внутри `<iframe sandbox="allow-forms">` с отдельного origin.

### Браузер и телеметрия

- iframe указывает на site-service (`sites.<host>`), а не на основной домен приложения.
- Все переходы идут через `GET /go?to=<artifact_ref>` на site-service: он пишет событие (сессия, откуда, куда) и отдаёт 302. Так клики и навигация логируются без JS внутри страниц.
- Формы корпуса отправляются на `POST /sim/forms` того же сервиса: он фиксирует ввод (факт, не значение секрета) и возвращает нейтральную страницу результата.
- Chrome (адресная строка, «проверить домен», «сертификат») — часть SPA; панели доверия запрашивают `GET /api/v1/sites/{host}/trust`.

### Dev и prod

- Dev: Vite на `:5173`, прокси `/api` → FastAPI `:8000`; site-service на `:8001`.
- Prod: `frontend/dist` монтируется в backend (`/`), API — `/api`, site-service — отдельный контейнер/порт; CSP и `X-Frame-Options` настраиваются раздельно для приложения и корпуса.

## Consequences

**Плюсы:** состояние и компоненты под контролем; один раз написанный `MailApp` используется в тренировке, практике и предпросмотре; типы API генерируются, дрейф контракта ловится компилятором; проще сделать качественный UI, чем на partials.

**Минусы и риски:** второй тулчейн (node, npm, линтер, сборка) и второй набор тестов; CI становится длиннее; бандл и кэш-инвалидация; SSE/WebSocket для «приходит письмо» нужно проектировать отдельно; соло-разработчику придётся держать в голове два стека.

**Что поддерживать:** `npm ci` и lock-файл в репозитории; генерация типов при изменении OpenAPI; запрет `dangerouslySetInnerHTML` через ESLint-правило; версия Node зафиксирована (`.nvmrc`), CI использует её же.

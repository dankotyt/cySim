# 0005. Веб-корпус: реестр брендов и реестр артефактов

- **Статус:** Accepted
- **Дата:** 2026-11-12
- **Связано:** ADR-0007 (комната ссылается на артефакты), ADR-0003 (iframe), ADR-0002 (no egress)

## Context

- «Браузер внутри стенда» должен открывать правдоподобные сайты, а сценарий — ссылаться на письма, PDF, USB-деревья и скрипты звонков. Всё это нужно показать без выхода в интернет.
- Клонировать реальные сайты нельзя (товарные знаки, авторское право, риск обучения на настоящем фишинге) и дорого (вёрстка 1000 сайтов руками).
- Сценарий (ADR-0007) не содержит HTML: он ссылается на артефакт по id. Значит, нужен стабильный реестр артефактов с версией сборки.
- Пул артефактов должен покрывать все темы и каналы, иначе генератор упрётся в «нет подходящего письма» и начнёт выдумывать.
- Целевой объём: **1000 брендов с первого этапа** и богатый пул артефактов на каждую тему.

## Decision

**Корпус — версионированный артефакт сборки (`corpus_build_id`), который состоит из реестра брендов, генератора сайтов и реестра артефактов. В рантайме LLM и GPU не участвуют.**

### Состав

| Часть | Формат | Назначение |
|---|---|---|
| `corpus/brands.yaml` | YAML | 1000 вымышленных компаний: имя, юрлицо, ИНН, домен, палитра, отрасль, контакты, сертификат |
| `corpus/sites/` | Jinja2 + CSS-токены | 4 layout-шаблона, страницы `home/about/contacts/login/support` |
| `corpus/artifacts/<topic>.yaml` | YAML | пул артефактов темы: `email`, `site_page`, `pdf`, `usb_tree`, `call_script` |
| `corpus/build_corpus.py` | Python | сборка в `corpus/dist/<build_id>/` + `manifest.json` |
| `site-service` | FastAPI | выдача страниц по allowlist, `/go`, `/sim/forms`, `/trust` |

### Артефакт

```yaml
- id: em-0042
  kind: email
  topic: phishing
  difficulty: 2
  brand_ref: br-0001
  mutation: null            # null = легитимный; иначе id мутации
  subject: "Сверка за Q3"
  body: "..."
  attachments: [{name: "Акт.pdf.lnk", size_kb: 12, mime: "application/x-ms-shortcut"}]
  links: [{text: "подтвердить", href: "https://romashka-prom.ru/auth"}]
  evidence_anchors: ["attachments[0].name", "links[0].href", "from.address"]
```

`artifact_ref = "<build_id>:<kind>:<id>"`. Сценарий пиннит `corpus_build_id`; артефакт с другим build_id считается несуществующим.

### Что генерируется и как

1. Легитимный сайт бренда: 4 layout × 8 палитр × отраслевой текстовый пакет. Логотип — SVG-монограмма, фотографий нет.
2. Клоны: 2–3 на бренд, домен мутируется (пропуск/перестановка/подмена, гомоглиф, TLD, дефис, поддомен, punycode), меняются 1–3 сигнала доверия.
3. Пул артефактов: **≥ 25 на тему** (18 тем → ≥ 450, цель 600), распределение по каналам: письма, страницы, PDF, USB, звонки.
4. Переиспользование: артефакт может встречаться в разных сценариях, но **не у одного сотрудника дважды** (таблица `artifact_usage`). Уникальность сценария — по набору объектов, цели и слотам, а не по артефакту.
5. Слоты (имя отправителя, сумма, дата) подставляются при генерации сценария из словаря тенанта; в артефакте остаётся шаблон.

### Мир тенанта

`world_id = HMAC-SHA256(world_secret, tenant_id || corpus_build_id)`; по нему переставляется «бренд → домен». `world_secret` живёт только на сервере и не попадает в репозиторий — иначе по открытому `brands.yaml` можно вычислить, какой домен легитимен в конкретной компании.

### Навигация и телеметрия без JS

- ссылки в страницах ведут на `GET /go?to=<artifact_ref>`; сервис пишет событие (сессия, откуда, куда) и отдаёт 302;
- формы — `POST /sim/forms`; сервис фиксирует факт отправки и возвращает нейтральную страницу;
- панель «Сертификат»/«WhoIS» — `GET /api/v1/sites/{host}/trust`, данные из реестра;
- HTML корпуса не содержит скриптов; CSP `script-src 'none'`.

### Качество сборки

Сборка падает, если: ссылка ведёт на неизвестный хост; на легитимной странице случайная опечатка в бренде/ИНН/телефоне; клон отличается не только заявленными сигналами; есть JS, внешние ресурсы или абсолютный URL на реальный сайт; страница > 60 КБ или ломается на 1280×720; в тексте есть «это фишинг» или lorem ipsum; у артефакта нет `evidence_anchors`, на которые ссылается генератор.

### Объём и цена

| Параметр | Значение |
|---|---|
| 1000 брендов × 6 легитимных страниц | 6 000 страниц |
| ~2,5 клона × 2 страницы × 1000 | ~5 000 страниц |
| пул артефактов | ~600 JSON + PDF (~30 МБ) |
| итого | ~250 МБ, сборка 3–6 минут CPU |
| рантайм | статика + один сервис, без LLM и GPU |

### Легальность

Только вымышленные компании; домены проверяются на NXDOMAIN при сборке и живут лишь внутри стенда; egress запрещён; корпус не публикуется наружу. Если корпус когда-нибудь станет публичным — переключение на `.example`/`.test` флагом сборки.

## Consequences

**Плюсы:** 11 000 страниц без ручной вёрстки; генератор сценариев получает стабильные id вместо свободного HTML; ground truth отделён от контента; корпус пополняется одной записью YAML; нулевая стоимость на запрос.

**Минусы и риски:** в open-source ground truth артефактов не является секретом (мутация видна в реестре) — секретом остаются `world_secret` и цель/набор объектов сценария; сборка и её тесты — отдельный пайплайн; 600 артефактов нужно написать и отревьюить; версионирование корпуса усложняет миграции (старые сценарии пиннят старый build_id); риск юридических претензий при неаккуратных именах.

**Что поддерживать:** `corpus_build_id` в сценариях и попытках; тесты консистентности при каждом добавлении бренда; проверку доменов раз в квартал; словари слотов на тенанта; лимит навигации на сессию (анти-scraping).
